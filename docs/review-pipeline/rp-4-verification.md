## 3. Corrections and choices (also in CONTRACTS.md)

1. **One migration, not two.** `publishing` `0003` holds both tables.
2. **No `path_template_mismatch` code.** A mismatch is a field error on `storage_root` or `relative_path`, with `error.code` = `validation_error` like every 400; a code of its own would need a change to the core exception handler.
3. **One message for an unknown, foreign or unreadable upstream** (`Unknown upstream file: <id>`), so an id outside the registrant's reach reveals nothing. A member who may register but not read files cannot name upstreams.
4. **Upstreams are locked** while the links are written, so a revoke cannot slip between the check and the insert.
5. **The loader is a list, not a page.** An unknown `file_type` code gives an empty list. Files whose checksum is `mismatch` or `missing` are not skipped; each row shows `checksum_state`.
6. **resolve-path** answers a 400 on `version_id` for an unknown version or a template it cannot fill, and a 404 when no template applies.
7. **Templates: PATCH only, no DELETE.** A project template needs a full member of the project. `project_id=studio` lists the studio's templates only. An extension written with a dot fills `{ext}` without it.
8. **Publishing reads Production only through its selectors**, as the dependency-direction test requires.
