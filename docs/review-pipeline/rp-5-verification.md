# RP-5 Media pipeline: verification

Branch `feature/rp-5-media-pipeline`, off `develop` at `8629ac83` (RP-4 merged and pushed). The plan and contracts are commit `cb1e5df3` (Q-RP-24 to Q-RP-31 answered as recommended). **Backend (WP 5.1 to 5.4), frontend (WP 5.5) and docs (WP 5.6) built, uncommitted.** Not pushed, not merged.

## 0. Read first

1. **Images since v4.1.0 are missing a production package (found and fixed here; needs a look at what is deployed).**
   - `.dockerignore` (commit `f233c679`, in v4.1.0 and later) has `**/media`. That drops every directory named `media`, including `backend/apps/production/api/serializers/media/`.
   - `apps/production/api/urls.py` imports `viewsets/media.py`, which imports that package. An image built from the old file raises `ModuleNotFoundError: No module named 'apps.production.api.serializers.media'`; checked in an image built here.
   - I did not run a released v4.1.0+ image. If one is deployed, check that it answers production routes.
   - The fix names the media and static folders by path (`backend/media`, `backend/static`, `backend/staticfiles`). `apps/core/tests/test_image_contents.py` fails when any package sits under a folder `.dockerignore` drops, and fails against the old file. It is a commit of its own, so it can go to `main` as a patch.
   - Images rebuilt with the fix: both packages are present, `/app/media` and `/app/static` are empty, and none of the 35,155 local media files is copied.
2. **A Celery fact the plan missed.** RP-5's upload is the first request-side code that queues a task. In a Django process `core.celery` is never imported: the current app is Celery's `default`, with no broker and no routes, so `shared_task.delay()` would not reach the `media` worker. The job is now sent by name through `core.celery` (`send_task`, `ignore_result`). A test sends it through an in-memory broker and reads it off the `media` queue; it fails with `.delay()` and fails without the route.
3. **Artists cannot upload.** Upload, retry and remove need `version.update`, held by org-admin, production-admin, vfx-supervisor and lead-artist (platform-admin holds every code); artists hold `version.view` only. Granting `version.update` to artists would also let them edit versions. A separate code would be a new decision.
4. **A formatter slip, undone.**
   - Running `ruff format` on `apps/production` reformatted 118 files RP-5 does not touch, and added noise to 5 RP-5 files.
   - The 118 were restored to `HEAD`; none had uncommitted changes.
   - The 5 were restored and RP-5's edits applied again by hand. Each was proven identical to the saved copy apart from formatting (`ruff format` of both gives the same text).
   - The production diff is RP-5 only (10 tracked files, 143 lines added, 10 removed).

## 3. Not done, or done differently

- **Compare tab.** It uses the same helper as the player, but has no test of its own for the review copy.
- **Expired links on list pages.** The version page, the review viewer and compare refetch before links expire. The Versions list and cards do not: after an hour without a refetch, a card's filmstrip and generated thumbnail can stop loading until the list is fetched again (on focus or navigation).
- **Hourly reload.** When a refreshed link replaces an expiring one, the player is remounted and starts again from the first frame.
- **No live browser run.** Nothing here ran the browser smoke or a live vitest file against a backend with a `celery-media` worker. The real-ffmpeg backend tests and the capture are the end-to-end evidence.
- **Not in RP-5:** sequences (EXR/DPX), OCIO, burn-ins, HDR, and object storage (ADR-0040, "Not decided here").
