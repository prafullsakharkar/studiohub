# RP-10 Loose ends of RP-5 and RP-6: verification

Branch `feature/rp-10-loose-ends`, off `develop` at `e5346727` (RP-1 to RP-6 merged; v4.7.0 released from `main` `52dd08e4`). The plan and contracts are commit `0e48ec50` (Q-RP-41 to Q-RP-45 answered as recommended). **WP 10.1 to 10.8 are commit `ff1bc2fc`**, merged into `develop` as `2cd9123d` and released in v4.8.0.

## 0. Read first

1. **Artists can now upload review movies to their own versions** (C-RP-26). This changes who may act, so it has a pre-deploy checklist entry. Nothing needs to be granted, because the seeded `artist` role already holds `version.create`. The right follows `Version.artist`: someone who stops being the version's artist loses it at once.
2. **Order of the checks on upload:** `version.view` (403), then reach (404), then the right (403), then the switch (409). So with review media off, the version's artist gets the 409 and anyone else the 403.
3. **A shot's or asset's Versions tab does not refresh itself.** The plan listed `EntityVersionsTab` for WP 10.1. That tab is a table without pictures, so it holds no signed link to renew. Only the Versions list refreshes (its cards, and the board on lists that have one).
4. **A live upload cannot go through the panel's file input.** jsdom's `File` loses its bytes in Node's `Request`. The live file posts the same multipart request with Node's own `fetch` and the artist's token. Because of that, the open page never saw a job and did not poll. The live test therefore waits for `ready` through the API and then opens the page. The polling itself (every 5 s while a job runs) is covered by the unit tests.
5. **The live harness's media thread is for the harness only.** It is switched on with `SYNC_LIVE_MEDIA=1`. Nothing else runs review media without the Celery `media` worker.

## 3. Known limits

- The live runs exercise the harness's thread, not the Celery `media` worker. The worker image and queue were checked in RP-5 (CI's container job).
- A renewed link restarts the picture's download: the browser loads the new address. The player keeps the frame and the playing state, but a slow connection can show a short stall at each renewal (once an hour).
- The panel's upload in a live run is not covered (jsdom, section 0, item 4). The route, token and field are the same.

## 4. Not done in RP-10

Nothing planned was left out. Found on the way and fixed in a separate, test-only commit after RP-10: the role smoke's no-role entry, out of date since `f37003e2` (section 2, "Role smoke"). The spec now counts the "No access yet" page as a refusal and expects it on all 61 routes. `run_role_smoke.sh --grep "user with no role"` passes (1 passed in 3.7 minutes; every route `refused (no role)`, no 403 call).
