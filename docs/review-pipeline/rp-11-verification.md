# RP-11 Notification depth (reviews and preferences): verification

Branch `feature/rp-11-notification-depth`, off `develop` at `81db4182` (v4.8.0). The plan and contracts are commit `fd07451c` (Q-RP-46 to Q-RP-50 answered as recommended). **WP 11.1 to 11.7 are built and not committed.**

## 0. Read first

1. **Client members stop seeing internal review comments** (C-RP-29). Before RP-11, every comment was served to anyone who could read the review, whatever its `is_client_visible`, and the composer never sent the flag. Now a client member is served only client-visible threads, and only those replies that are client-visible too. Whatever a client member writes is stored client-visible. Internal comments written before this release disappear from client members' reviews. This has a pre-deploy checklist entry.
2. **"The artist of a version" now includes the assignee of its task** (a deviation from the plan's table). The live run showed it: the artist was told nothing, because the Versions screen never sets `Version.artist` and the backend does not default it. Review decisions and review comments now go to the version's `artist` and to the assignee of its live task, each once. These are the same people `version_status` tells (RP-6). Reverting it is one helper (`_version_people` in `notification_sources.py`). Say if you want the plan's narrower rule instead.
3. **One migration, not two** (`notifications` `0002_rp11_review_kinds_and_preferences`). It is additive, with no data step.
4. **A client member signs in with MFA.** This is not new: external members owe MFA enrolment (TPN TM-007, `MFA_REQUIRE_EXTERNAL`). The live file enrols the client first. A studio that adds client members should expect each one to be asked to set up two-factor authentication at their next sign-in.
5. **The live run is a new file**, `reviewNotifications.live.test.tsx`, rather than an extension of `notifications.live.test.tsx` as planned. It needs a client member with MFA, a producer and a supervisor, which the RP-6 file does not set up.

## 3. Known limits

- A muted kind is not kept for later: unmuting brings back nothing (C-RP-30, as planned).
- The composer's "Internal" offer follows `/auth/me`. A person who becomes a client member during a session sees it until the next `/auth/me`. The server stores their comments client-visible either way.
- The role smoke was not rerun: RP-11 changes no route and no permission gate.
