Branch `feature/rp-12-media-depth`, off `develop` at `0fe2dbf5` (RP-11 merged). The plan and contracts are commit `d38af8e9` (Q-RP-51 to Q-RP-56 answered as recommended). **WP 12.1 to 12.8 are committed as `f2b84225`, merged into `develop` (`292b5060`) and released in v4.9.0.** develop's first CI run failed on an RP-6 notifications test that still called `_finish` the old way (fixed in `46b163c3`); the image scan and the dependency audit flagged `dnspython` and `tornado` (bumped in `dd89ac3d` and `0a1c1ee9`).

## 0. Read first

1. **The 2,000-frame cap fits the job budget only on a media worker with 4 or more CPUs.** The plan asked for a measurement (Q-RP-52). It was run in the `worker` image with the app's own command builders on 2K half-float EXR (zip16, with noise so it does not compress unrealistically). Proxy, thumbnail and filmstrip together took:
   - 0.49 s a frame on 4 CPUs: 2,000 frames in about 16 minutes, inside the 25-minute budget;
   - 1.08 s a frame on 2 CPUs: about 36 minutes, so only about 1,350 frames fit.

   The compose files give `celery-media` no CPU limit. The default stays at 2,000, and the pre-deploy checklist says to set `REVIEW_MEDIA_MAX_FRAMES` to 1200 or lower on a smaller worker. If you would rather have a safer default (1,200), it is one line in `config/env.py`.
2. **One migration**, `production` `0010_rp12_sequences_and_burn_ins`, additive with no data step, as planned. Deploying needs a rebuilt `worker` image (for the font) and a reload of nginx (for the part route). Without the reload, a part over 10 MB is refused with 413. Both are in the pre-deploy checklist.
3. **One bug was found by the capture, not by the tests:** the three new settings were defined in `components/storage.py`, but `config/settings/base.py` imports each name explicitly, and they were missing there. The module's test fixture set them, which hid the gap; the first real request was a 500. They are now imported. A new test reads them from the settings module itself.
4. **`missing_frames` comes in two types.** It holds numbers in a part's 200 and strings in a refused completion's 400, because DRF turns validation-error values into strings. The frontend shows the sentence, so nothing depends on it, but a script reading the 400 should expect strings (CONTRACTS, "Details settled while building RP-12").
5. **There is no `docs/apps/production.md`** to extend (plan WP 12.8). Review media is documented in ADR-0040, which is amended instead.

## 3. Known limits

- The colour rule is fixed (EXR from linear to sRGB, everything else as stored). The panel says a copy is not for colour approval. A LUT or OpenColorIO is a later phase (Q-RP-53).
- In the browser, "Upload a sequence" picks a folder with `webkitdirectory`, which every current browser supports; "Choose frames" covers the rest.
- A part is sent by the browser as one request; a failed part stops the upload where it is, and the panel shows the unfinished upload, which can only be cancelled and sent again (there is no resume).
- The role smoke was not rerun: RP-12 adds no permission gate (the panel follows C-RP-26's rule, already covered).

## 4. Not done in RP-12

Nothing planned was left out. The sequence flow has its own capture tool instead of extending the movie one (section 1, WP 12.7).
